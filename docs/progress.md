## 2026-08-06 - Task 2-7 - 作図の補助線・折りたたみ可否の注意表示・紙のめり込み警告を追加

- **作図補助**(CPE-005): ツールレールに「作図」を追加(常設9個、上限10個以内)。サブメニューで二等分・垂線・等分(2〜8)・角度線(22.5/45/30/15°刻み)を選び、展開図で点や線をクリックすると補助線が引かれる。画面の左上に「次に何をクリックするか」を常に1行で出す(Escで中止)。等分は各等分点を端点にした短い目印を出すので、次に線を引くときその点へ正確に吸着できる
- **平らに畳めるかの注意表示**(CPE-009): 内部の点ごとに前川定理(山−谷=±2)と川崎定理(1つおきの角の和=180°)を検査し、合わない点を展開図で橙色の丸で示す。**操作は止めない**。点にカーソルを乗せると「山と谷の本数が合いません」「向かい合う角の和が合いません」と理由が出る。補助線は折りに関与しないので数えない
- **紙のめり込み警告**(SIM-007): 立体表示の面同士が突き抜けていないかを調べ(AABBで絞ってから三角形の貫通判定)、見つかれば「紙が重なって食い込んでいます」を3D画面の警告バッジに出す。折り目でつながった面・同一平面の重なり・平らに畳んだ状態(z≒0)は正常として数えない。面400枚でdebug約9ms
- Tauriコマンドは9個のまま。画面で使う作図の計算はTS側(`lib/construct.ts`)に同じ式を置き、結果を既存の`edit_apply`(補助線の追加)で送っている
- テストはRust 174件→192件、画面169件→190件。全5検査合格(clippyは並行作業中の`ori3-layers`のテストを除いて確認)
- 既知の問題: 局所条件は必要条件なので、通っても層の重なりで畳めない形はある。めり込み判定は凸でない面を扇状に割るため、まれに実際より広く見積もる(警告を出しすぎる側)

## 2026-08-06 - Task 2-6c - 紙をつかんで動かす直感的な折り操作に変更

- 位置をきっちり決めたいときのために、Ctrl+ドラッグで折り線を引いてパネルで指定する操作も残した

## 2026-08-05 - Task 2-6b前半 - どんな折り方でも表せる汎用の折り操作を追加

- 「実際の紙で折れるのにアプリで表現できない」状態を無くすため、畳んだ状態から畳んだ状態への**どんな紙の動きでも表せる1つの部品**を作った。動かす紙を「層+畳んだ面での領域+施す動き(鏡映の重ね方や回転)+重なりのどこへ入れるか」で指定する。領域の境目がそのまま新しい折り線になり、展開図へ自動で書き加わる
- これまで「折り線を1本足す」ことしかできなかったため作れなかった動きが作れるようになった: 折り目を開く(角度を0度に戻す)/ 紙がまったく動かず重なり順と山谷だけが変わる遷移 / 層ごとに反対向きへ回す(中割り折り・かぶせ折りの中身)/ 鏡映2回=回転を含む動き(つぶし折り・ねじり折りの中身)/ 開く動きと折る動きを1回にまとめる(花弁折りの中身)/ 領域の中だけ重なりを裏返す(沈め折りの中身)
- 山谷は最終的な重なり順から決め直すようにした。これで回転を含む動きでも展開図の山谷が正しくなり、折りたたみの決まり(山と谷の本数の差が2)を満たす
- 断るのは形が決まらない指定(線が点になっている・どちら側か決まらない・対象が無い)だけ。紙が裂ける選び方は警告して続行する。失敗したときは展開図を一切変更しない
- 既存の「畳んだ紙にまとめて折る操作」はこの部品への薄い委譲に置き換えた。既存のテストは1件も書き換えずに全て合格している
- テストはRust 156件→165件(洗い出した全ケース+重なり順の見た目検証+手順からの再生一致)。全5検査合格
- 既知の問題: 花弁折り・つぶし折りの「技法ボタン」と、画面から自由に層をつまんで動かす操作は後半の作業(ロードマップTask 2-6bの残り)

## 2026-08-05 - Task 2-5修正 - 紙の重なり順が上下逆に記録される問題を修正

- 折るたびに記録される「紙の重なり順」が、画面に見える重なりと上下逆になることがあった。正方形を半分に折るいちばん普通の1手目でも起きていて、重なり順を使う表示・検査・書き出しと「いちばん上の1枚を折る」指定が、すべて逆の紙を指していた

- 折り操作の出力を、記録の前に表示と同じ基準へそろえるようにして解消した(裏返しの関係になるときは重なり順も裏返す)
- 引きかけの折り線が「元に戻す」や手順の選び直しをまたいで生き残り、別の形の上で引いた線が黙って適用される問題も直した。形が変わったら折り線は捨て、案内を出す
- 「動かす側」の選択肢が画面の左右と一致しないことがあったため、言葉で左右を言わず立体表示のハイライトで示す形に変えた。折り線の座標表示もmmにした
- テストはRust 135件→141件、画面110件→116件(折り終わる直前の高さから本当の重なりを読み取って突き合わせる検証を追加)。全5検査合格。実機で「1手目から重なりが正しいこと」を確認した
- 既知の問題: 表示の基準が最初の面なので、折るたびに立体の位置と向きが動いて見えること自体は残っている(重なり順は正しく追従する)
