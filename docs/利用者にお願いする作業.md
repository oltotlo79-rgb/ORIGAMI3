# 利用者にお願いする作業

この文書で行うのは二つだけです。画面の使いやすさを確かめる部品を入れることと、公開後に4ファイルが同じ内容か確認することです。
部品の問題を調べる作業、更新のお知らせの記録、Node 22の版と40文字の識別子の確認は、GitHubの自動検査が行います。
各番号は一行ずつ実行します。赤い文字が出たら、その番号で止め、同じ行を繰り返しません。

## 1. 画面の使いやすさを確かめる部品を入れる（5〜15分）

これは、画面の押す場所や入力欄を機械で確かめられるようにするために必要です。製品の画面や使い方は増やしません。

1. Windowsキーを押し、`PowerShell`と入力します。`Windows PowerShell`を押します。管理者として開く必要はありません。
2. 次を貼り付け、Enterキーを押します。

   ```powershell
   Set-Location -LiteralPath "C:\Users\oltot\Documents\git-projects\ORIGAMI3\apps\desktop"
   ```

   **こうなっていればOKです**: 行の左側が `PS C:\Users\oltot\Documents\git-projects\ORIGAMI3\apps\desktop>` で終わります。

3. 次を貼り付け、Enterキーを押します。

   ```powershell
   npm.cmd install --save-dev --save-exact axe-core@4.12.1
   ```

   **こうなっていればOKです**: 最後が赤い文字ではなく、`added`または`up to date`を含む表示になります。

4. 次を貼り付け、Enterキーを押します。

   ```powershell
   npm.cmd pkg get devDependencies.axe-core
   ```

   **こうなっていればOKです**: `"4.12.1"`と表示されます。

5. 次を貼り付け、Enterキーを押します。

   ```powershell
   npm.cmd ls axe-core --depth=0
   ```

   **こうなっていればOKです**: `axe-core@4.12.1`を含む行が表示されます。

6. 次を貼り付け、Enterキーを押します。

   ```powershell
   Select-String -LiteralPath 'package-lock.json' -Pattern 'sha512-s7iGf5GaVMxEG0ENN9x+xTr7GFZCb1ZP/1uATUpCEK2X78nDB3RwbtFCo9pGAf9ru+VwoQ464DkaLEeRM08wJA=='
   ```

   **こうなっていればOKです**: 上の長い文字を含む行が1行以上表示されます。

7. 次を貼り付け、Enterキーを押します。

   ```powershell
   npm.cmd run build
   ```

   **こうなっていればOKです**: 最後が赤い文字ではなく、終了コード0で終わります。

8. 次を貼り付け、Enterキーを押します。

   ```powershell
   npm.cmd run lint
   ```

   **こうなっていればOKです**: 最後が赤い文字ではなく、終了コード0で終わります。

9. 次を貼り付け、Enterキーを押します。

   ```powershell
   npm.cmd run test
   ```

   **こうなっていればOKです**: 最後が赤い文字ではなく、終了コード0で終わります。すでに見つかっている画面操作の問題が出た場合は、期待する内容を変えて通そうとせず、表示を担当者へ渡します。

### うまくいかないとき

- 手順3が失敗した: 同じ行を繰り返さず、表示された文章を最初から最後まで担当者へ渡します。手順2から再開します。
- 手順4〜6の表示が違う: 自分で別の版を入れず、表示を担当者へ渡します。手順3から再開します。
- 手順7〜9が失敗した: その番号で止め、表示を担当者へ渡します。担当者の返事があるまで再開しません。

## 2. 公開後に、ダウンロードした4ファイルを確認する（10分）

これは、公開ページから受け取った4ファイルが、公開時に記録したものと同じであることを確かめるために必要です。公開済みのファイルを置き換える操作はしません。

1. GitHubのプロジェクト画面で`Releases`を押します。見つからない場合は右側の`About`、`Releases`、`Tags`の順に見ます。今回の版を押し、`Assets`を開きます。
2. 次の6ファイルを1件ずつ押し、同じフォルダーへ保存します。ファイル名は変えません。

   ```text
   ORIGAMI3_0.5.0_setup.exe
   ORIGAMI3_0.5.0_x64.msi
   ORIGAMI3_0.5.0_portable.exe
   ORIGAMI3.pdf
   ORIGAMI3_0.5.0_SHA256SUMS.txt
   ORIGAMI3_0.5.0_artifact-record.json
   ```

3. Windowsキーを押しながら`E`を押します。上部の場所を示す欄へ次を入力し、Enterキーを押します。

   ```text
   C:\Users\oltot\Documents\git-projects\ORIGAMI3
   ```

4. 上部の`新規作成`、`New`、フォルダーの印のいずれかを押し、`downloaded-release-assets`と入力してEnterキーを押します。すでにある場合は開きます。
5. 手順2の最初の4ファイルを`downloaded-release-assets`へ移します。`SHA256SUMS.txt`と`artifact-record.json`は、プロジェクトの`verification\improvement-roadmap\10-supply-chain`へ移します。移動先が無い場合は、次をPowerShellへ貼り付け、Enterキーを押します。

   ```powershell
   New-Item -ItemType Directory -Force -Path "C:\Users\oltot\Documents\git-projects\ORIGAMI3\verification\improvement-roadmap\10-supply-chain"
   ```

6. PowerShellへ戻り、次を貼り付け、Enterキーを押します。

   ```powershell
   Set-Location -LiteralPath "C:\Users\oltot\Documents\git-projects\ORIGAMI3"
   ```

   **こうなっていればOKです**: 行の左側が `PS C:\Users\oltot\Documents\git-projects\ORIGAMI3>` で終わります。

7. 次を貼り付け、Enterキーを押します。

   ```powershell
   $recordRoot = Join-Path $PWD 'verification\improvement-roadmap\10-supply-chain'
   ```

   **こうなっていればOKです**: 何も表示されません。

8. 次を貼り付け、Enterキーを押します。

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/supply-chain-verify-release-hashes.ps1 -ManifestPath (Join-Path $recordRoot 'ORIGAMI3_0.5.0_SHA256SUMS.txt') -DownloadedDirectory (Join-Path $PWD 'downloaded-release-assets') -RecordPath (Join-Path $recordRoot 'ORIGAMI3_0.5.0_artifact-record.json') -ResultPath (Join-Path $recordRoot 'download-hash-verification.json')
   ```

   **こうなっていればOKです**: `download-hash-verification.json`が保存先にでき、4件すべてが一致しています。

### うまくいかないとき

- `Releases`または`Assets`が見つからない: 画面に見える見出しと住所を担当者へ渡します。別の版や別のファイルを選びません。
- 6ファイルのどれかが無い: そろっている名前を担当者へ知らせます。代わりのファイルを選びません。
- 手順8で一致しない、またはファイルが不足している: ダウンロードしたものを消さず、`download-hash-verification.json`と表示された文章を担当者へ渡します。手順2からやり直しません。

## この作業機について

この作業機のCPUは、一般的なWindowsパソコンとは違う種類（ARM64）です。そのため、一部のプログラムを組み立てられないことがあります。
エラーに`aarch64`または`ARM64`が出ていたら、CPUの種類が原因の可能性が高いです。表示を残して担当者へ渡し、自分で追加の開発用ソフトを入れません。

組み立てに失敗して `C:\Users\oltot\AppData\Local\Temp\ori3-target-supply-chain-user` が残った場合は、まずエラー表示を担当者へ渡します。今回残ったフォルダーは統括が片付けます。次回は担当者から片付けてよいと連絡を受け、`cargo`と`rustc`が動いていないことを確認してから、エクスプローラーでそのフォルダーを選び、`Delete`または「削除」を押します。
