## 11. リリース時に必ず最新化するもの（2026-08-11 利用者指示）

- **リリースのたびに、ヘルプと取扱説明書を画像も含めて最新の状態にする。** 実装した機能が解説に載っていない状態でリリースしない。
- **起きたこと**: v0.3.0の後に多数の機能追加・不具合修正が入ったが、説明書PDFはv0.3.0時点のままで、ヘルプにも新機能の解説が無かった。利用者の指摘で発覚した。
- **画像も対象**: 画面の見た目が変わる変更（区画の広さ、色分け、通知の追加など）が入ったら、**既存のスクリーンショットは全て古くなる**。撮り直す。
- **仕組みでの対策**: `scripts/check-release-ready.ps1` を実行し、次を自動で検査してから タグを打つ。
  1. バージョン番号が4ファイル・5か所（`Cargo.toml`／`apps/desktop/package.json`／`apps/desktop/package-lock.json`のルート直下と`packages[""]`内の2か所／`apps/desktop/src-tauri/tauri.conf.json`）で一致している。
  2. 説明書PDFが、`apps/desktop/src/`・`apps/desktop/package.json`・`docs/manual/assets/`の中で最も新しいものより新しい。根拠は、未コミットの変更が無ければ最後に変えたコミットの時刻、あればファイルの更新時刻。
  3. 説明書の生成元である`apps/desktop/package.json`のバージョン表記がタグと一致している。PDF本体の文字は図形化されており安定して抽出できないため読んでいない。
  4. ヘルプ（`apps/desktop/src/help/`配下）の章が説明書より新しくない。
  5. 利用者への報告記録がリリース日と一致し、`scripts/check-report-log.ps1` が完全性表現・残件数・進捗率を共通ロードマップsnapshotへ照合している。
  6. `scripts/get-roadmap-status.ps1 -Format Report -RequireComplete` がロードマップ全件を対象に件数とhashを表示し、未チェックが1件でもあれば失敗する。加えて `scripts/doc-link-audit.ps1 -CheckTraceability` が証拠台帳3成果物と現在のsnapshotのbyte/hash一致を検査する。
- **全段実行の証明**: 出力の `RELEASE_STAGES planned=6 begun=6 ended=6` が一致しなければ合格にしない。第6段は報告へ貼る `Roadmap-Snapshot:` と `Roadmap-Progress:` を共通生成器の出力のまま表示する。
- **リリース手順の順序**: 機能凍結 → ヘルプ・説明書の更新 → 画像の撮り直し → 説明書の再生成 → `check.ps1` → `check-ci.ps1` → `check-release-ready.ps1` → コミット → タグ

### 11.1 解説に載せる範囲

- **利用者の操作と画面表示に関することだけを載せる。** 内部の計算方式、データ構造、最適化、アルゴリズム名は載せない。
- 判断基準: 「利用者が画面で見る」「利用者が操作する」もののみ。利用者が知らなくても使えることは書かない。
- 内部用語（ソルバー、hard/soft、warm start、ヤコビアン等）を利用者向けの文章に出さない。
- 理由: 利用者の指示「ユーザーの操作や表示に関するもの以外は載せなくていい」。説明書は操作の手引きであり、設計文書ではないため。
