# 公開後の確認

新しい版を公開した後にだけ、この文書を使います。公開ページから受け取った4ファイルが、公開時に記録したものと同じかを確かめます。
各番号は一行ずつ実行します。赤い文字が出たら、その番号で止め、同じ行を繰り返しません。

## 公開後に、配布物の中身の一覧とダウンロードした4ファイルを確認する（15分）

リリースしないと確かめられないため、この確認は公開後に行います。公開ページから受け取った4ファイルが、公開時に記録したものと同じか、各ファイルの中身の一覧と照合用ファイルが4件そろっているかを確かめます。公開済みのファイルを置き換える操作はしません。

1. GitHubのプロジェクト画面で`Releases`を押します。見つからない場合は右側の`About`、`Releases`、`Tags`の順に見ます。今回の版を押し、`Assets`を開きます。

   **こうなっていればOKです**: 今回の版の`Assets`見出しと、ダウンロードできるファイル一覧が見えます。

2. 次の15ファイルを1件ずつ押し、同じフォルダーへ保存します。ファイル名は変えません。

   ```text
   ORIGAMI3_0.5.0_setup.exe
   ORIGAMI3_0.5.0_x64.msi
   ORIGAMI3_0.5.0_portable.exe
   ORIGAMI3.pdf
   ORIGAMI3_0.5.0_component-list-status.json
   ORIGAMI3_0.5.0_setup.exe.components.cdx.json
   ORIGAMI3_0.5.0_x64.msi.components.cdx.json
   ORIGAMI3_0.5.0_portable.exe.components.cdx.json
   ORIGAMI3.pdf.components.cdx.json
   ORIGAMI3_0.5.0_setup.exe.sha256
   ORIGAMI3_0.5.0_x64.msi.sha256
   ORIGAMI3_0.5.0_portable.exe.sha256
   ORIGAMI3.pdf.sha256
   ORIGAMI3_0.5.0_SHA256SUMS.txt
   ORIGAMI3_0.5.0_artifact-record.json
   ```

   **こうなっていればOKです**: 同じフォルダーに、上の15ファイルが同じ名前でそろいます。

3. Windowsキーを押しながら`E`を押します。上部の場所を示す欄へ次を入力し、Enterキーを押します。

   ```text
   C:\Users\oltot\Documents\git-projects\ORIGAMI3
   ```

   **こうなっていればOKです**: エクスプローラーで`ORIGAMI3`のフォルダーが開きます。

4. 上部の`新規作成`、`New`、フォルダーの印のいずれかを押し、`downloaded-release-assets`と入力してEnterキーを押します。すでにある場合は開きます。

   **こうなっていればOKです**: `downloaded-release-assets`というフォルダーが開きます。

5. 手順2の最初の4ファイルを`downloaded-release-assets`へ移します。残り11ファイルは、プロジェクトの`verification\improvement-roadmap\10-supply-chain`へ移します。移動先が無い場合は、次をPowerShellへ貼り付け、Enterキーを押します。

   ```powershell
   $releaseRecordDirectory = 'C:\Users\oltot\Documents\git-projects\ORIGAMI3\verification\improvement-roadmap\10-supply-chain'; if (Test-Path -LiteralPath $releaseRecordDirectory) { '照合用の保存先を確認しました' } else { New-Item -ItemType Directory -Force -Path $releaseRecordDirectory | Out-Null; if (Test-Path -LiteralPath $releaseRecordDirectory) { '照合用の保存先を用意しました' } else { '照合用の保存先を用意できませんでした。担当者へ知らせてください' } }
   ```

   **こうなっていればOKです**: `照合用の保存先を確認しました`または`照合用の保存先を用意しました`と表示され、最初の4ファイルは`downloaded-release-assets`、残り11ファイルは照合用の保存先にあります。

6. PowerShellへ戻り、次を貼り付け、Enterキーを押します。

   ```powershell
   Set-Location -LiteralPath "C:\Users\oltot\Documents\git-projects\ORIGAMI3"
   ```

   **こうなっていればOKです**: 行の左側が `PS C:\Users\oltot\Documents\git-projects\ORIGAMI3>` で終わります。

7. 次を貼り付け、Enterキーを押します。

   ```powershell
   $recordRoot = Join-Path $PWD 'verification\improvement-roadmap\10-supply-chain'; '照合結果の保存先を決めました'
   ```

   **こうなっていればOKです**: `照合結果の保存先を決めました`と表示されます。

### 1. 公開した中身の一覧を確認する（5分）

8. 次を貼り付け、Enterキーを押します。公開時に作られた中身の一覧と照合用ファイルの状態を確認します。

   ```powershell
   $statusPath = Join-Path $recordRoot 'ORIGAMI3_0.5.0_component-list-status.json'; if (-not (Test-Path -LiteralPath $statusPath -PathType Leaf)) { '中身の一覧の状態を記録したファイルがありません。担当者へ知らせてください' } elseif ((Select-String -LiteralPath $statusPath -Pattern '"state": "complete"' -SimpleMatch -Quiet) -and (Select-String -LiteralPath $statusPath -Pattern '"componentListCount": 4' -SimpleMatch -Quiet) -and (Select-String -LiteralPath $statusPath -Pattern '"hashSidecarCount": 4' -SimpleMatch -Quiet)) { '4ファイルの中身の一覧と照合用ファイルが作られたことを確認しました' } else { '中身の一覧または照合用ファイルの作成が完了していません。担当者へ知らせてください' }
   ```

   **こうなっていればOKです**: `4ファイルの中身の一覧と照合用ファイルが作られたことを確認しました`と表示されます。

9. 次を貼り付け、Enterキーを押します。手順2で受け取った照合用ファイル11件がそろっていることを確認します。

   ```powershell
   $requiredRecordNames = @('ORIGAMI3_0.5.0_component-list-status.json','ORIGAMI3_0.5.0_setup.exe.components.cdx.json','ORIGAMI3_0.5.0_x64.msi.components.cdx.json','ORIGAMI3_0.5.0_portable.exe.components.cdx.json','ORIGAMI3.pdf.components.cdx.json','ORIGAMI3_0.5.0_setup.exe.sha256','ORIGAMI3_0.5.0_x64.msi.sha256','ORIGAMI3_0.5.0_portable.exe.sha256','ORIGAMI3.pdf.sha256','ORIGAMI3_0.5.0_SHA256SUMS.txt','ORIGAMI3_0.5.0_artifact-record.json'); $missingRecordNames = @($requiredRecordNames | Where-Object { -not (Test-Path -LiteralPath (Join-Path $recordRoot $_) -PathType Leaf) }); if ($missingRecordNames.Count -eq 0) { '照合用ファイル11件がそろっています' } else { "照合用ファイルがありません: $($missingRecordNames -join '、')。担当者へ知らせてください" }
   ```

   **こうなっていればOKです**: `照合用ファイル11件がそろっています`と表示されます。

### 2. ダウンロードした4ファイルを照合する（10分）

10. 次を貼り付け、Enterキーを押します。

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/supply-chain-verify-release-hashes.ps1 -ManifestPath (Join-Path $recordRoot 'ORIGAMI3_0.5.0_SHA256SUMS.txt') -DownloadedDirectory (Join-Path $PWD 'downloaded-release-assets') -RecordPath (Join-Path $recordRoot 'ORIGAMI3_0.5.0_artifact-record.json') -ResultPath (Join-Path $recordRoot 'download-hash-verification.json')
   ```

   **こうなっていればOKです**: 結果が表示されます。次の手順で照合結果を判定します。

11. 次を貼り付け、Enterキーを押します。

   ```powershell
   if ($LASTEXITCODE -eq 0) { '4ファイルすべてが一致しました' } else { '一致しないファイルがあるか、照合を実行できませんでした。担当者へ知らせてください' }
   ```

   **こうなっていればOKです**: `4ファイルすべてが一致しました`と表示され、`download-hash-verification.json`が保存先にできます。

### うまくいかないとき

- `Releases`または`Assets`が見つからない: 画面に見える見出しと住所を担当者へ渡します。別の版や別のファイルを選びません。
- 15ファイルのどれかが無い: そろっている名前を担当者へ知らせます。代わりのファイルを選びません。
- 手順5で保存先を用意できない: 表示を担当者へ渡します。手順5から再開しません。
- 手順8または手順9で確認できない: ダウンロードしたものを消さず、表示された文章を担当者へ渡します。手順2からやり直しません。
- 手順11で一致しない、または照合を実行できない: ダウンロードしたものを消さず、`download-hash-verification.json`と表示された文章を担当者へ渡します。手順2からやり直しません。

## この作業機について

この作業機のCPUは、一般的なWindowsパソコンとは違う種類（ARM64）です。そのため、一部のプログラムを組み立てられないことがあります。
エラーに`aarch64`または`ARM64`が出ていたら、CPUの種類が原因の可能性が高いです。表示を残して担当者へ渡し、自分で追加の開発用ソフトを入れません。

組み立てに失敗して `C:\Users\oltot\AppData\Local\Temp\ori3-target-supply-chain-user` が残った場合は、まずエラー表示を担当者へ渡します。今回残ったフォルダーは統括が片付けます。次回は担当者から片付けてよいと連絡を受け、`cargo`と`rustc`が動いていないことを確認してから、エクスプローラーでそのフォルダーを選び、`Delete`または「削除」を押します。
