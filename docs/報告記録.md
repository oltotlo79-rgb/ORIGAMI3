## 2026-08-25 13:45 — 利用者報告の不具合の原因を特定し、中核を修正

### 利用者の報告（2026-08-25 01:07〜01:40）

### 原因（**確定。v0.5.0 に存在**）

**立体の計算が、書類に入っていない隠れた出発点（直前の計算結果）を使っていた。**

```
いまの姿:   書類 ＋ 希望角 ＋ 隠れた出発点 → 立体
あるべき姿: 書類 ＋ 折り手順             → 立体（ただ1つに決まる）
```

要件 §2・規約§8「3D状態は保存しない。展開図＋折り手順から再生して導出する」に違反していた。

### 修正結果（実機・実測）

| 項目 | 修正前 | 修正後 |
|---|---:|---:|
| 実際の角度の差 | 251.02° | **0°** |

| 重なり順が違う面 | 6面 | **0面** |
| 表裏が違う面 | 4面 | **0面** |
| どの面が描かれたか | 310,226画素 | **0画素** |
| 最終の色 | 312,540画素 | **0画素** |

**取り消し1回で完全に元へ戻る。やり直し1回で戻る。**

**既存3作品（折り鶴・鳥の基本形・やっこさん）の見え方は変わらない**（画像がバイト単位で一致）。

### 残っている課題

**確定した瞬間に形が跳ぶ**（折り目19で 0.637774、紙の幅＝1）。

**3つの要件が同時に成り立たないことが実測で判明。**

2. 同じ書類からは必ず同じ形（今回の修正）
3. 確定時に跳ばない

**利用者の判断（2026-08-25）: ①②を優先し、③は諦める。跳びはできる限り小さくする。**
