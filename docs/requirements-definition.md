# ORIGAMI3 要件定義書

作成日: 2026-08-05
状態: 承認待ち(レビュー中)

---

## 1. 目的と背景

ORIGAMI3は、**展開図を描きながら3Dモデルで折り紙を折り、新作を設計するためのデスクトップアプリ**である。

前身のORIGAMI2(Tauri 2 + React + Three.js + Rust)は要件のほぼ全てを実装したが、以下の理由で「非常に複雑で使いにくい」状態に陥った。

| ORIGAMI2の問題 | 原因 |
|---|---|
| 実装が重く進まない | 厳密有理数演算・数学的証明・連続衝突判定を全面採用(衝突判定だけで17万行) |
| 画面がごちゃごちゃ | 単一画面にインスペクタ24セクション + ダイアログ11種を平置き |
| 折る操作が難しい | 剛体キネマティクス + 証明ゲートにより、操作が「判定保留」で頻繁に停止 |
| 保守が困難 | `editor.rs` 21,736行、`App.tsx` 5,963行(useState 66個)、Tauriコマンド191個 |

ORIGAMI3はコードを引き継がず新規に開発し、**「実用上正しい」ことを「証明可能なほど正しい」より優先する**。

## 2. 設計原則(全要件に優先する規律)

0. **表現の完全性(最優先)。** 実際の紙で折れる操作は、すべてアプリで表現できなければならない。「物理的には折れるのにアプリでは表現できない」状態を作らない。特定の技法だけを個別対応するのではなく、**任意の平坦状態から平坦状態への紙の動きを表せる汎用の折り操作**を土台に置き、技法はその上のマクロとして実装する。層の枚数・偶奇や特定の形状に依存する制限を設けない。定義不能な入力(線がどの層も横切っていない等)以外は、断らずに実行して必要なら警告する。
1. **原則としてf64 + 明示的許容誤差(ε)で計算する。** 限定例外として、展開図の頂点座標だけは、座標誤差が原因だと実測で確認できた場合に限り `Q(√2) = { a + b√2 | a,b は有理数 }` で厳密に扱ってよい。例外の範囲は頂点座標の作図・交点・同一点判定までとし、3D剛体折り、たわみ、衝突判定、描画は常にf64 + εのままにする。これ以外の厳密有理数演算・証明書・決定論的超越関数は作らない。2026-08-10の悪魔の予備折りは実測で構造誤りと判明したため、この例外を使う厳密型は導入していない。
2. **止めずに警告する。** ソルバー不収束・紙のめり込み・平坦折り条件違反が起きても操作は継続させ、警告表示のみ行う。ユーザーの操作をブロックするゲートを作らない。
3. **常設UIは4区画に固定する。** ツールレール / 2D展開図 / 3Dビュー+タイムライン / コンテキストパネル(1枚)。固定パネルを増やす機能追加は要件から却下する。
3b. **直感的に触れること(最優先級)。** 説明を読まなくても操作が分かることを優先する。具体的には (a)**紙を直接つかんで動かす**操作を主とし、パネルでの数値・選択肢の入力は補助に留める (b)操作の**結果を実行前にプレビュー**で見せる (c)今どのモードで何ができるかを画面上で常に示す (d)できない操作はボタンを消すのではなく、なぜできないかを短い日本語で伝える (e)専門用語を避け、折り紙で使う言葉(山折り・谷折り・かぶせ折り…)で表示する。この原則は個別のUI要件より優先する。
4. **Tauri IPCコマンドは「コマンド1個 + 操作enum」に集約する。** 個数の上限は設けない(2026-08-08改訂: ユーザー指示によりコード量・個数の数値上限を撤廃)が、同種の操作を別コマンドとして増やさず、既存コマンドのenum拡張を先に検討する。
5. **コードの規模上限は設けない**(2026-08-08改訂)。ただし機能に寄与しない複雑さを持ち込まないこと。1ファイル1,000行以内を目安とし、超える場合は分割する。
6. **フロントエンドの状態はZustandストアに一元化する。** コンポーネント内`useState`は表示専用の一時状態(ホバー等)に限る。
7. **3D状態は保存しない。** 折り状態は常に「展開図 + 折り手順」から再生して導出する(決定性を保証)。

## 3. 対象ユーザーと主ユースケース

- 対象: 折り紙の新作を設計したい個人(開発者自身)。
- 主ユースケース(この一連の流れがアプリの背骨):
  1. 提案ウィザードで「頭1・尾1・足4、それぞれの長さと太さ」のように骨格を指定し、基本展開図を生成する
  2. 生成された展開図をグリッド・作図補助で編集する
  3. 3Dビューで1折りずつ順番に折る。畳んだ紙の上に折り線を直接描いて重ねて折ることも、各ヒンジの角度を調整して立体形状を確認することもできる(3Dでの操作は展開図に自動反映される)
  4. 展開図を修正すると、記録済みの折り手順が自動再生されて修正後の形を即確認できる
  5. 完成したら展開図(SVG/PNG)と折り図(PDF)を書き出す

## 4. スコープ

### 4.1 やること(v1)

- 正方形・長方形の紙の展開図編集(グリッド + 作図補助)
- ヒンジごとの角度指定による剛体折り3D表示(ハイブリッド方式、§7)
- 1折りずつの手順記録・自動再生・タイムライン編集
- 複雑系技法まで対応(中割り・かぶせ・花弁・段折り・開いてつぶす・沈め折り・ひだ寄せ・ねじり折り)
- 骨格指定による展開図自動提案(木構造理論ベース)
- 展開図SVG/PNG書き出し、折り図PDF/SVG書き出し
- 独自形式(.ori3)の保存/読込、Undo/Redo、自動保存、クラッシュ復旧

### 4.2 やらないこと(明示的な非目標)

以下はv1で実装しない。**設計の余地も残さない**(将来やる場合は要件から再定義する)。

- 全面的な厳密有理数演算、数学的証明、証明書(certificate)機構。§2設計原則1で許す「展開図の頂点座標だけのQ(√2)」を唯一の限定例外とし、3D剛体折り・たわみ・衝突判定・描画へは拡張しない
- 紙厚モデル(紙厚は常にゼロ)
- めり込み・衝突の厳密防止(検出して警告するのみ。それも簡易判定)
- **物理的に正確な布・紙のシミュレーション**(材質・重力・摩擦・皺の再現)。たわみは§6.3 SIM-012〜014の範囲の**見た目の近似**に留める
- 任意多角形の紙(正方形・長方形のみ)
- FOLD / DXF / OBJ / STL / glTF の入出力
- 画像認識・参考画像からの自動設計
- 折り技法ファイルの共有機構
- 幾何制約ソルバー(数式入力・拘束(等長・平行等)の管理)
- レイヤー(作図レイヤー)、注釈、下絵表示
- macOSの正式対応(ビルド可能性の維持のみ)
- 多言語対応(日本語のみ)

## 5. 用語定義

| 用語 | 定義 |
|---|---|
| 展開図 (CP) | 紙の上の折り線集合。線種は輪郭・山・谷・補助の4種 |
| 面 (Face) | 展開図の線で囲まれた閉領域。自動導出される |
| ヒンジ | 隣接する2面の間の折り線。剛体折りの回転軸 |
| ヒンジ角 | ヒンジの折り角度。0°=平ら、+180°=完全な山折り、−180°=完全な谷折り |
| driver | ユーザーが直接指定するヒンジ角。それ以外のヒンジ角はソルバーが追従させる |
| 平坦状態 (FlatState) | すべての面が同一平面上に畳まれた状態。面の2D配置 + 層順序で表す |
| 層順序 | 平坦状態における面の上下関係。下から上への面の全順序リストで表す(面IDは導出値で不安定なため、永続化時は各面をCP座標系の内部代表点で参照する) |
| 折りステップ | 折り手順の1単位。driver群 + 到達時層順序 + 技法種別からなる |
| 技法 | 中割り折りなど、複数の折り線が連動する定型操作。折りステップの種別として記録 |
| 折り図 | 折り手順を人間向けに図示した手順書(PDF/SVG) |

## 6. 機能要件

優先度: **MUST**(v1必須) / **SHOULD**(v1に入れたいが遅延可)。実装時期は§11のマイルストーン(M1〜M4)で示す。

|---|---|---|---|

| PAP-002 | 紙厚はゼロとして扱う。厚みに関する計算・表示は行わない | MUST | M1 |
| PAP-003 | 表面色・裏面色は、折り紙らしい日本語名付き24色パレットから選べる。選択中の色を明示し、パレット外は「その他の色」のカラーピッカーで自由指定でき、3D表示へ反映される | MUST | M1 |

| CPE-005 | 作図補助: 角の二等分線、点から線分への垂線、線分のn等分点(2〜8)、22.5°刻み方向線 | MUST | M2 |

### 6.3 3D折りシミュレーション (SIM)

| ID | 要件 | 優先度 | 時期 |
|---|---|---|---|
| SIM-001 | 展開図・3Dでヒンジを選択し、角度をスライダー(−180°〜+180°)と数値入力で指定できる。Ctrl+クリックで追加/解除し、展開図の矩形選択も利用して複数選択できる。複数時は識別番号・ホバー強調付きの個別スライダーを縦に並べ、先頭の一括スライダーで全てを同じ絶対角度へ設定する。連続操作は16ms間引き・runLatestを維持し、選択数によらず1回のpose_solveへまとめる | MUST | M1 |
| SIM-002 | 剛体折りソルバー: driver角を固定し、従属ヒンジ角を数値解法で追従させて全面の3D姿勢を求める。詳細は§7 | MUST | M1 |
| SIM-003 | ソルバー不収束時は直前の収束解を表示し続け、警告バッジを出す。操作は止めない | MUST | M1 |
| SIM-004 | 平坦状態では層順序を保持し、3D表示は層ごとに微小オフセット(表示専用)を付けて重なりを見せる | MUST | M2 |
| SIM-005 | 折り操作: **3Dビュー上で畳んだ紙の上に折り線を直接描き**、対象層(既定は跨る全層の可動側)を選んで一括で折れる。描いた線は各層の面を通じて展開図へ引き戻され、対応する折り線が自動追記される(3D→2Dの反映) | MUST | M2 |
| SIM-006 | 技法ツール: 中割り折り・かぶせ折り・花弁折り・段折り・開いてつぶす折り(M2)、沈め折り(open sink)・ひだ寄せ・ねじり折り(M4)。対象と折り線を指定すると必要な折り線群と層変化を自動生成する | MUST | M2/M4 |
| SIM-011 | **汎用の折り操作**: 技法として名前が付いていない紙の動きも表現できること。畳んだ状態で層を選び、目標の位置・向きへ動かすと、必要な折り線・層順序の変化を自動で求めて適用する(設計原則0の実現手段)。層の枚数や偶奇による制限を設けない | MUST | M2 |
| SIM-012 | **紙のたわみ表現**: 面を細かく分割し、折り目以外の場所でも紙が滑らかに曲がる形を近似して表示する。鶴の胴の膨らみ、風船の丸みなどを自然に見せる。**オン/オフを切り替えられ、既定はオフ**(既存の平らな板としての表示・計算を変えないため) | MUST | M5 |
| SIM-013 | **膨らませる操作**: 袋になっている作品(風船など)に空気を入れて膨らませる。膨らみの強さを指定でき、3D画面で見ながら調整できる | MUST | M5 |
| SIM-014 | **たわみ表示でも紙の重なり順を保つ**: たわみ計算で層どうしがすり抜けないこと。重なり順は既存の層モデル(§7.2)の値を拘束として使う。破れた場合は警告を出して続行する(止めない) | MUST | M5 |
| SIM-015 | たわみの状態は「たわみのパラメータ(硬さ・膨らみの強さ)」として仕上げの手順に記録でき、再生で再現される。**頂点の位置そのものは保存しない**(3D状態は保存しない設計を維持) | MUST | M5 |
| SIM-016 | **折り切り時の貫通警告**: 折り操作が完全な平坦状態(t=1.0)へ達したときに層順序の矛盾を検査し、紙の貫通があれば「この折り方だと紙が突き抜けています」のように原因が分かる日本語の警告バッジを表示する。操作は止めない | MUST | M2 |
| SIM-017 | **巻き込み折り目の提案**: 折った紙(フラップ)が重なりの単一の縁にぶつかる典型ケースでは、その縁の線分を折りの反転写像でフラップ上へ戻した線を追加折り目として求め、「指定した場所以外に、ここへ折り目がつきます」と2D展開図・3Dビューの両方で実行前または警告時に強調表示する。コンテキストパネル等の非モーダルUIで承認すれば追加折り目を適用して貫通を避け、拒否すれば元の折りを維持して警告だけを表示する。複数の縁との同時衝突など一意に求められない複雑ケースは提案せず、SIM-016の警告へフォールバックする | MUST | M2 |
| SIM-018 | **現在操作中の折り目を最優先する自然追従**: いま利用者が動かしている折り目（手順再生では現在再生している折り動作の対象。仕上げの角度(Pose)は除く）だけを指定角へ最優先で固定し、前の手順・以前に利用者が明示した角度はなるべく保つ目標、それ以外は自由な折り目として、紙のつながりが成立するよう周囲を追従させる。目標角を譲ったときは、変更した折り目と希望角からの差を既存の3D警告位置およびコンテキストパネルへ非モーダル表示する。不収束時も最優先角を保った最良の有限形を表示し、有限形を生成できない場合だけ直前の有限形へ戻して、いずれも操作を止めない。3D座標・warm start・追従診断は保存せず、展開図と折り手順から再導出する | MUST | M2 |
| SIM-007 | めり込み(面同士の交差)は防止しない。簡易判定で検出したら3Dビューに警告バッジを出す | MUST | M2 |
| SIM-008 | 3D表示: 表裏の色分け、面の境界線表示、軌道カメラ(回転・ズーム・パン) | MUST | M1 |
| SIM-009 | 完成形を平らに畳まず角度を付けて仕上げる「ポーズ」ステップを記録できる | MUST | M2 |
| SIM-010 | 3Dビュー上でヒンジをクリック選択できる。H/Lキー等で隣のヒンジへ選択を移動できる | SHOULD | M2 |

## 7. 折りエンジン方式(ハイブリッド: B-lite + 層管理)

採用方式は「**表示と操作は剛体折り、記録と複雑技法は平坦状態の層モデル**」の2層構造。

### 7.1 剛体キネマティクス層(立体表現の担当)

- 展開図の面隣接グラフに全域木を取り、根面を基準平面に固定。ヒンジ角に沿って回転変換を合成し各面の3D姿勢を得る。
- 内部頂点(ループ)がある場合、ループ一周の回転合成が恒等変換になる拘束を、driver角固定・従属角可変のGauss-Newton法(数値ヤコビアン + Levenberg減衰)で満たす。
- f64演算。収束判定・特異点回避は許容誤差εで明示的に扱う。
- **衝突判定・貫通防止は行わない。** アニメーション中のめり込みは許容する(SIM-007の簡易警告のみ)。

### 7.1b 汎用の折り操作(表現の完全性の実現手段)

平坦状態から平坦状態への紙の動きは、数学的には「動かす層の集合」と「それらに施す等長変換(反射の合成)」で表せる。反射の軸がそのまま折り線になる。したがって次の1つのプリミティブがあれば、名前の付いた技法もそうでない動きもすべて表現できる:

- 入力: 動かす層(面の集合)、目標の等長変換(または反射軸の列)、対象位置
- 処理: (a)必要な折り線を求めて展開図へ引き戻して追加 (b)紙のつながりを検査し、動かす層と動かさない層の境界が折り線になっているかを確認(なっていなければ裂ける指定として警告)(c)新しい面配置と層順序を決定 (d)このステップが動かす全ての折り線をDriverLineとして記録
- 「折り目を開く」動きは「その折り目を0°へ駆動する」として同じ枠組みで表せる

技法(中割り・かぶせ・花弁・つぶし・沈め・ひだ寄せ・ねじり)は、このプリミティブを呼ぶマクロとして実装する。層の枚数・偶奇の仮定を置かず、動かす層の分割は**実際の紙のつながり**から決める。

### 7.1c たわみ層(見た目の担当・SIM-012〜015)

剛体折りが求めた「平らな板の集まり」の姿勢を**基準の形**として受け取り、その上で紙を細かく分割して曲げる後処理層。**重なり順は§7.2の層モデルが持ち続ける**ため、折り操作・手順記録・折り図出力は一切変更しない。

- 各面を細かい三角形に分割し、頂点を動かして次の条件を近似的に満たす形を求める(位置ベースの反復計算。反復回数と順序を固定して**決定的**にする):
  - 紙は伸びない(分割した辺の長さを保つ)
  - 紙は曲がるが硬さがある(隣り合う三角形の角度をなるべく平らに保つ。硬さは調整可)
  - 折り目の角度は剛体折りが求めた値を保つ(強い拘束)
  - 袋の内側に空気圧を与えられる(膨らませる操作。SIM-013)
  - **層どうしがすり抜けない**(層順序を「層iは層i+1より下」という拘束として与える。SIM-014)
- 出力は細かい三角形の網。3D表示・当たり判定はこれを使う
- **オフのときは従来どおり面ごとの多角形をそのまま表示**し、計算も行わない(既定オフ)

### 7.2 平坦状態・層順序層(手順記録の担当)

- 折りステップの区切り(平らに畳まれた状態)では、面の2D配置(鏡映変換の合成)と層順序(面の全順序リスト)を組合せ的に記録する。「重なり順は正確に」はこの層で保証する。
- 折り操作(SIM-005)は平坦状態の上で定義し、対象層の鏡映 + 層順序の更新 + 展開図への折り線引き戻しを原子的に行う。
- 沈め折り等、剛体折りで物理的に再現できない技法は平坦状態間の遷移として定義し、アニメーションは見た目のヒンジ角補間で表現する(物理検証なし)。

### 7.3 2層の関係

- 折り手順 = 「driver群(どの折り線をどの角度へ。折り線は展開図座標の線分として永続化し、後続の折りによる辺の分割に耐える) + 到達時の層順序」の列。
- 再生時: 各ステップのdriver角を0→目標へ補間して剛体折りで動かし、ステップ末尾で層順序を適用する。
- 途中で止めた立体状態はポーズ(SIM-009)としてそのまま記録・鑑賞できる。

## 8. 自動提案方式(木構造理論・簡易版)

1. 骨格 = 根付き木。葉が角(頭・尾・足)、内部辺が胴。各辺に長さ、各葉に太さ係数(膨らみ)を持つ。
2. 葉を円(半径=角の長さ)、内部辺を川(幅=辺の長さ)として、正方形/長方形上に円・川充填を数値最適化(目的: 縮尺最大化、制約: 円同士の非重複・紙内包含)で配置する。初期配置は紙の角・辺への貪欲配置 + 乱数シード。紙内包含を「円中心が紙内」とするか「円全体が紙内」とするかは作業6の測定後に決定する。現行実装の中心包含は測定用の基準であり、確定要件ではない。
3. 充填結果から軸多角形を作り、各多角形を簡易分子(ウサギ耳分子。非三角形は扇状分割)で埋めて折り線を生成する。
4. 生成した展開図に局所平坦折り判定(CPE-009)を掛け、違反頂点は警告付きでそのまま提示する(生成を失敗扱いにしない)。

精度目標: 「頭1・尾1・足4」程度の骨格で、鶴系の基本形に相当する折り可能な展開図が得られること。厳密な最適性・完全な平坦折り可能性は保証しない。

| M2 | 層順序 + 折り操作 + 基本技法 + 手順記録/自動再生 + 自動保存 | **折り鶴**: 1折りずつ折って完成でき、展開図修正後に自動再生される |
| M3 | 自動提案ウィザード | 「頭1・尾1・足4」の骨格から折り可能な基本展開図が生成される |
| M4 | 沈め折り・ひだ寄せ・ねじり + 折り図/画像書き出し | **伝承のカエル**: 折って完成でき、折り図PDFが出力される |
| M5 | 紙のたわみ表現(SIM-012〜015) | **風船**: 折って膨らませると丸みのある立体になり、層がすり抜けない。**折り鶴**: 胴が自然に膨らむ。たわみをオフにすると従来どおりの表示に戻る |

## 12. リスクと対策

| リスク | 対策 |
|---|---|
| 剛体折りソルバーが複雑CPで不安定 | 不収束でも直前解を表示して続行(SIM-003)。driver角の変化を小刻みに分割して追従させる |
| 技法(中割り等)の自動折り線生成が対象形状によって失敗する | 失敗時は手動の折り操作(SIM-005)で代替できる設計にする。技法は「折り操作のマクロ」であり専用データを持たない |
| 自動提案の充填最適化が局所解に陥る | 乱数シード違いの複数候補(PRO-005)。厳密最適は要件にしない |
| スコープ肥大(ORIGAMI2の再来) | 数値上限は2026-08-08に撤廃したが、§2の規律(操作enum集約・状態一元化・UIの分かりやすさ)と§4.2の非目標リストを変更する場合は本書の改訂を必須とする。ORIGAMI2の失敗要因は行数そのものではなく「厳密演算の全面化」と「UIの平置き」であり、§2設計原則1の頂点座標限定例外を越える厳密化とUIの平置きは引き続き禁止する |
