## 残っている未実装・制限

- **紙のたわみ(風船の丸みなど面そのものが曲がる表現)はできない**。紙を平らな板の集まりとして扱う設計のため、立体的な仕上げは多面体になる(要件で意図的に対象外。変更するには要件の見直しが必要)
- つぶし折りで奥側の層が本体につながっている形、ねじり折りの中央多角形の形状指定に制限あり(いずれも警告して続行)
- 3Dで引っ張る操作: 左右対称の相手を同時に動かす機能は未実装(片羽ずつ)。根になる面自体はつかめない。引いた形を手順に残すと、角度の丸めのため再生時に収束の警告バッジが点く(形のずれは見た目に出ない)
- 途中に挿入した折りが後続手順と幾何的に矛盾する場合、後続はタイムラインで赤表示+警告になる(自動修復はしない)
- 左右対称描画は線を引くときのみ有効(削除・線種変更は片側ずつ)

## 未消化の確認事項

- **Windows側でのアプリ起動ができない**(Windowsのアプリ制御機能が desktop.exe の起動を拒否する。テスト用の実行ファイルは削除→再作成で回避できるがGUI本体は不可)
- **WSL(Ubuntu 24.04 + WSLg)では起動・描画を確認済み**(2026-08-06)。ビルド依存は導入済みで、Windows側で画面をビルド→WSLでアプリ本体を起動する手順で動く。画面全体(ツールレール9個・展開図エディタ・3D表示・操作ヒント・タイムライン・下部パネル)が正しく描画されることをスクリーンショットで確認
  - 手順: (1)Windowsで `cd apps/desktop; npm run build` (2)WSLで `cd apps/desktop/dist && python3 -m http.server 1420 &` (3)WSLで `LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe WEBKIT_DISABLE_DMABUF_RENDERER=1 ./target/debug/desktop`(ソフトウェア描画の指定が無いとGPU初期化に失敗して即終了する)
  - **WSLgのウィンドウには合成マウス入力(SendInput/mouse_event)が届かない**ため、クリック操作の自動確認はできない。操作を伴う目視確認はユーザー側での実施が必要
- 画面側の自動テスト基盤(DOM環境)が未導入のため、入力欄・カメラ操作などは目視確認のみ
- 平らに畳んだ紙は全ての層が同じ高さ(z=0)に重なるため、立体表示がちらついて見える(SIM-004の層オフセット表示が未実装のため。2-7以降で対応)
- 画面の描画そのもの(手順の札の表示・画面更新に合わせた再生の駆動)は自動テストで検証できていない。DOM環境(jsdom+Testing Library)の導入はTask 2-6以降で検討する
- Task 2-6の設計制約: 技法マクロは「そのステップが動かす折り線をすべて記録」する必要がある(手順再生が全ての折り線を固定値として解くため)
- 花弁折り(petal)・開いてつぶす(squash)が未実装。この2つは既存の折り目を**開く**(角度を0°へ戻す)操作を含み、折り線を足すことしかできない `fold_through` の合成では作れない。実装には「畳んだ状態で指定した折り目を開く」プリミティブ(層順序の決定を含む)が要る
- 中割り折りは、折り上がり(t=1)の形と重なり順は正しいが、再生の途中(t<1)では先端が紙の外側を大回りして見える。フラップを開く動きは前の手順の折り目を保ったままでは表せないため(折り図の書き出しでは折り上がりだけを使うので実害は無い)。かぶせ折り・段折りは途中の動きも折り上がりと一致する
- 中割り折り・かぶせ折りで先端をどちら向きに回すかは、紙のつながり(折り線が横切る折り目でつながった層は反対向きに回る)から決めている。層の数が奇数でも、重なりの一部だけを選んでも折れる。紙が裂ける選び方(選んだ層の先端が、選ばなかった層の先端とつながっている場合)は警告して続行する — 断らないのは「実際に折れるものをアプリで表現できない」状態を作らないため
