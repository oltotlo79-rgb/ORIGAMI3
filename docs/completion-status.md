## 未消化の確認事項

- アプリ実機でのGUI目視確認(やっこさんを描いて折る)がユーザー確認待ち
- 画面側の自動テスト基盤(DOM環境)が未導入のため、入力欄・カメラ操作などは目視確認のみ
- 平らに畳んだ紙は全ての層が同じ高さ(z=0)に重なるため、立体表示がちらついて見える(SIM-004の層オフセット表示が未実装のため。2-7以降で対応)
- 画面の描画そのもの(手順の札の表示・画面更新に合わせた再生の駆動)は自動テストで検証できていない。DOM環境(jsdom+Testing Library)の導入はTask 2-6以降で検討する
- Task 2-6の設計制約: 技法マクロは「そのステップが動かす折り線をすべて記録」する必要がある(手順再生が全ての折り線を固定値として解くため)
- 花弁折り(petal)・開いてつぶす(squash)が未実装。この2つは既存の折り目を**開く**(角度を0°へ戻す)操作を含み、折り線を足すことしかできない `fold_through` の合成では作れない。実装には「畳んだ状態で指定した折り目を開く」プリミティブ(層順序の決定を含む)が要る
- 中割り折りは、折り上がり(t=1)の形と重なり順は正しいが、再生の途中(t<1)では先端が紙の外側を大回りして見える。フラップを開く動きは前の手順の折り目を保ったままでは表せないため(折り図の書き出しでは折り上がりだけを使うので実害は無い)。かぶせ折り・段折りは途中の動きも折り上がりと一致する
- 中割り折り・かぶせ折りで先端をどちら向きに回すかは、紙のつながり(折り線が横切る折り目でつながった層は反対向きに回る)から決めている。層の数が奇数でも、重なりの一部だけを選んでも折れる。紙が裂ける選び方(選んだ層の先端が、選ばなかった層の先端とつながっている場合)は警告して続行する — 断らないのは「実際に折れるものをアプリで表現できない」状態を作らないため
